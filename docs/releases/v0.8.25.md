# Ariadne v0.8.25

An explicit full-backup plan now selects **one independently restored full recovery
set**, without accumulating separate runtime, configuration or collection snapshots.

## Changed

- Capture snapshots directly inside the pending full set. Publish only after
  independent file, Qdrant, SQLite and configured-model recovery succeeds.
- Runtime upgrades, same-version reinstalls and client integration reuse the
  verified full keeper. Pre-upgrade checks require it to contain the installed
  binaries and application; a stale keeper requires a fresh full backup first.
- Remove only native snapshot sources recorded by the successful full recovery
  receipt. Cleanup failure retains the published full and supports a verified retry.
- Preserve old full manifests, collection restore logs, retention audit and access
  history in immutable audit archives outside rotation.
- Leave existing standalone runtime/snapshot/config copies untouched until an
  explicit cleanup plan is approved. Component-only installations without a
  full-backup plan retain their existing compatibility mode.
- Normalize the physical audit-source path so full rotation works through
  platform path aliases without weakening traversal checks.

## Verification

Tests cover repeated full backups without separate generations, failed recovery
preserving old copies, exact native-source cleanup and retry, preserved snapshot
audit, missing or corrupt full proofs, and stale runtime upgrade rejection.
Go tests, race checks, build/lint, native Windows/Linux and rendered EN/UK site
checks gate publication. Live deployment separately verifies restored full
recovery, the installed runtime, one-copy layout and preserved audit.
