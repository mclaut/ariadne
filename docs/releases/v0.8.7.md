# Ariadne v0.8.7

This patch release makes tray service controls observable and verifiable from
the initial click through Qdrant and Ollama recovery, tray replacement, and the
final completion notification.

## Fixed

- **Launchd-safe Homebrew discovery.** The macOS service controller resolves
  `brew` from standard Homebrew locations when launchd's restricted `PATH` does
  not contain it, so a tray restart actually cycles Ollama as well as Qdrant.
- **Recovery after a partial stop failure.** `ariadnectl restart` always attempts
  the start phase, then returns joined stop/start errors instead of abandoning
  the stack between phases.
- **Completion notification after tray replacement.** The old tray appends the
  verified result before exiting; its launchd replacement posts the final
  notification and appends a delivered marker. Only the newest operation can
  be reported, so stale pending events are not replayed.
- **Useful platform errors.** Unix and Windows service commands retain their
  output, making the actual platform failure visible in CLI, tray, and logs.

## Added

- **Before/after service verification.** Start, Stop, and Restart wait for the
  requested Qdrant and Ollama state. Restart checks that managed service PIDs
  changed, and a running Qdrant collection must remain green.
- **PID observability.** Tray rows, text status, and JSON status expose Qdrant
  and Ollama PIDs on macOS, Linux, and Windows.
- **Operation diagnostics.** Tray logs record duration, before/after snapshots,
  command output, and the exact verification error. Progress, verified success,
  and actionable failure notifications use the active tray language.
- **Append-only notification journal.** Pending and delivered restart events are
  separate records under Ariadne runtime state; delivery never rewrites or
  truncates the journal.

## Changed

- **Conflicting controls are disabled while work is active.** Service controls,
  maintenance, update, backup, and export cannot overlap and produce ambiguous
  results.
- **Status polling is shared and more tolerant.** The tray uses the same
  structured status decoder for normal polling and service verification, with
  enough time for loaded local services to answer.
