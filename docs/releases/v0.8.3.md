## What's new

- **Human-approved cross-project recall.** `all_wings: true` no longer acts as
  authorization by itself. The MCP server creates an append-only pending
  request, and recall proceeds only after the user approves that request in the
  Ariadne tray and the client retries with its `approval_id`.
- **Short-lived, scoped grants.** A cross-project grant lasts 15 minutes and is
  bound to the MCP client session, active wing, and collection. Approval for
  curated memory does not silently grant access to the raw `sessions` archive.
- **Origin-aware ranking.** Approved cross-wing candidates receive a 0.70
  origin weight and occupy at most two of five normal results while local
  memories retain priority. Results disclose whether they are local or
  cross-wing and show the applied weight.
- **Separate credential approval.** The new `credential_access` MCP tool creates
  a distinct tray request for one exact source wing, target wing, credential
  name/path, and purpose. An approved grant is valid for five minutes and is
  consumed once. Ariadne never reads, returns, or stores the credential value.
- **Append-only approval audit.** Requests, tray decisions, and one-time grant
  consumptions are separate immutable JSON records under the private runtime
  state directory. `ariadnectl approvals` lists pending requests without
  providing an approval bypass.
- **Localized tray controls.** The tray displays the oldest pending request,
  its bounded purpose/scope, Approve and Deny actions, queue size, and desktop
  notifications in every supported language.

## Security boundaries

- Weighting is applied only after authorization and is not used as an access
  control.
- Exact-ID recall also requires the active wing; a memory owned by another wing
  follows the same tray approval path.
- Credential approval is currently an audited authorization handshake for the
  agent policy. It is not yet an operating-system credential broker, so the
  filesystem client must still enforce the exact approved resource and purpose.
- Secret values remain forbidden in Qdrant, approval requests, logs, and
  transcripts.
