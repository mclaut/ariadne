# Ariadne v0.8.32

Nightly consolidation stops setting aside Ukrainian diaries that are full of
code: the curator's language is now judged by the prose, not by paths,
commands and identifiers.

## Fixed

- **The language check and the curator agree.** The check counted every Latin
  letter, so a Ukrainian diary full of paths, commands and identifiers looked
  English. The prompt and the repair guidance, which looked at Ukrainian
  letters, told the curator to write Ukrainian. The curator obeyed, the check
  rejected the memory, and the retry repeated the same instruction, so these
  batches were set aside on every run. Code spans, URLs and identifier-like
  tokens (paths, dotted or snake_case names, flags, numbers) are now removed
  before the language is measured, and the check, the prompt hint and the
  repair guidance share one function, so they always name the same language.
  In a dry run with `qwen2.5:14b`, language deferrals fell from 11 to 2.

## Changed

- **Language deferrals name both languages.** A batch set aside for language
  now reads, for example, `output language differs from source (expected
  Ukrainian, got latin script)`.

## Upgrade

Update from the tray. The consolidation pipeline revision moves to
`atomic-v5`, so batches deferred by earlier releases are reconsidered once by
the next maintenance run. Memories, backups and settings are kept.

## Verification

Regression tests cover a code-heavy Ukrainian diary that a raw letter count
reads as Latin: a Ukrainian memory is accepted, an English one is rejected
with the expected language named, and the prompt and repair guidance both ask
for Ukrainian. An English diary that quotes Ukrainian stays English.
`go build`, `go vet` (darwin, linux, windows), `go test -race`,
`golangci-lint` v2.11.4 and `govulncheck` v1.10.0 (0 reachable
vulnerabilities) pass on go1.26.11.
