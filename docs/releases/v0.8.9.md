# Ariadne v0.8.9

This reliability release fixes a real Qdrant file-descriptor exhaustion
incident under many concurrent Codex and Claude Code sessions. It also makes
the failure visible before the memory database becomes unavailable.

## Root cause

- The Qdrant Go client silently defaulted to a pool of three persistent gRPC
  connections for every Ariadne MCP process.
- 62 simultaneously active MCP processes therefore held 186 Qdrant gRPC
  connections before normal segment, WAL, and HTTP descriptors were counted.
- macOS launchd supplied Qdrant with its default soft limit of 256 open files.
  At descriptor 255, Qdrant could no longer accept connections or flush segment
  state and WAL metadata, producing intermittent recall/save failures.
- Every MCP startup also retried creation of every payload index and ignored
  index errors, adding avoidable work and masking degraded storage.

## Fixed

- **One gRPC connection per MCP process.** Ariadne now explicitly sets the
  Qdrant client pool size to one, matching the serialized stdio MCP workload.
- **Production-sized macOS descriptor capacity.** The Qdrant launchd template
  sets `SoftResourceLimits.NumberOfFiles` to 8192 instead of inheriting 256.
- **No payload-index storm at startup.** Ariadne reads the collection schema
  once and creates only missing indexes. A concurrent index-creation race is
  confirmed by rereading the schema; every other storage error fails startup.
- **Graceful client shutdown.** MCP, hook, importer, installer, and maintenance
  paths close their Qdrant connection when they finish.
- **Early warning.** `ariadnectl status`, the tray, and `doctor.sh` report open
  descriptors versus the configured limit and warn at 75 percent pressure.

## Database recovery and verification

- The incident showed resource-exhaustion and failed flush messages, but no
  corruption or panic signature.
- The local activation procedure restarts Qdrant with the raised limit, checks
  WAL recovery output, verifies the collection is green and point counts are
  stable, performs exact and semantic recall plus idempotent save checks, and
  validates the append-only metrics SQLite database.
- No restore, collection replacement, or destructive cleanup is performed.

## Verification

- full `go test -race ./...`, `go build ./...`, and `golangci-lint run`
- macOS launchd plist lint and descriptor-limit contract test
- Linux amd64/arm64 and Windows amd64 cross-builds
- production site lint, build, and rendered English/Ukrainian tests
- live high-concurrency descriptor check after immutable v0.8.9 activation
- post-restart Qdrant collection, WAL, recall/save, backup, and metrics-database
  integrity checks
