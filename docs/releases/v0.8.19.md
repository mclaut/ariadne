# Ariadne v0.8.19

Ariadne now keeps one verified recovery copy per component. Backup storage no
longer grows through ten recent snapshots plus an unlimited historical archive.

## Changed

- **One verified copy per component.** Configured Qdrant collections retain one recovery snapshot. Upgrades keep one previous runtime and one previous copy of each changed client configuration.
- **Recovery checked before rotation.** Snapshot size and SHA-256 must match Qdrant; an isolated local Qdrant restores the snapshot, checks the source count and vector schema, and reads every point with its payload and vectors.
- **Bounded backup storage.** After successful verification, older matching downloaded/archive snapshots and redundant native snapshots expire automatically. Older historical backup states are intentionally discarded.
- **Working state stays available.** Live memory, session data, access-request history and audit logs remain outside rotation. Modified or in-use previous generations block replacement.

## Operator migration

- `ariadnectl backup` creates, checksum-verifies and restores a snapshot in an
  isolated loopback-only Qdrant with separate data directories. All point IDs,
  payloads and vectors are read before the replacement is published.
- A durable manifest binds the snapshot hash, size, recovery time, point count,
  point digest and vector schema. Failed verification preserves the prior copy.
- `ARIADNE_BACKUP_COLLECTIONS` is explicit. Its absence backs up only the
  configured collection. For an owned memory and raw-session pair, set it to
  `ariadne,sessions`; no collection-discovery grant is inferred.
- Older managed snapshots lose their historical payload/metadata revisions when
  rotation succeeds. Preserve required checkpoints outside the managed names.
- Custom full sets, exports, access decisions and audit evidence are retained.
- Installers preserve checksummed runtime/app and changed-client configuration
  copies before replacing installed files. Running or modified backup generations
  defer replacement. Installation and backup locks prevent competing rotations.

## Compatibility

Recovery verification requires a compatible local Qdrant executable. A remote
source keeps its existing explicit transport/authentication policy. Verification
uses a fresh private directory and sanitized environment, never live storage.
Existing access-menu grouping, pagination and exact-ID approval behavior remain.

## Verification

Regression tests cover corruption, failed restore, post-verification mutation,
source count/schema mismatch, precise point IDs, competing generations, modified
or symlinked backup paths, bounded retention and process cancellation. Full Go,
race, build, lint and rendered EN/UK website checks gate publication.
