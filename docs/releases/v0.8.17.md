# Ariadne v0.8.17

Access requests remain visible from creation through a decision, expiration, or
one-time consumption. The tray exposes the full retained queue and history.

## Fixed

- Each request has its own approval controls bound to its exact ID.
- System prompts rotate across eligible requests, preferring requests not yet
  shown. Each dialog yields after 30 seconds while the request remains pending
  until its original deadline.
- Per-request retry cooldowns prevent repeated oldest-request prompts from
  starving newer requests.

## Added

- Explicit pending, approved, denied, expired, and consumed statuses in the tray.
- `ariadnectl approvals --all` and `--all --json` expose retained lifecycle history.
- Approved status explains that the client must retry with `approval_id`.

## Security and compatibility

- Request, decision, and consumption records are preserved. Status/history reads
  never grant access or consume a grant.
- Existing pending and grant deadlines, session and scope bindings, and one-time
  credential enforcement remain unchanged.
- Closing or timing out a system dialog grants no access. Tray controls remain
  available until the request expires.
- Approval does not automatically resume an MCP client. Tests exercise the
  explicit retry after a human decision and reject a reused one-time grant.

## Verification

- Queue rotation, isolated cooldowns, and retained expired/consumed history tests.
- MCP approval continuation and one-time replay rejection tests.
- Targeted race tests, full Go tests/build, lint, and rendered website checks.
