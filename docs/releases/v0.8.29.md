# Ariadne v0.8.29

Updates no longer leave Qdrant stopped, and nightly consolidation drains the
whole diary queue in one run.

## Fixed

- **Updates keep Qdrant running.** `launchctl bootout` returns before launchd
  has finished removing the job, so the installer's immediate `bootstrap` of
  the same service could fail with `Bootstrap failed: 5: Input/output error`.
  The v0.8.28 update then stopped with Qdrant unloaded, and the next
  maintenance run failed. The installer now waits until launchd has released
  the old job before starting it again and retries the start, for the Qdrant,
  maintenance and tray agents.
- **Consolidation drains the whole queue in one run.** One 15-minute deadline
  covered the entire consolidation run; when it expired, every remaining batch
  failed at once and was deferred for the whole pipeline revision, so it was
  never retried. Now:
  - there is no run-wide deadline: every model request keeps its own timeout;
  - Ollama errors and timeouts are retried in place (three attempts per batch)
    and are never deferred; only deterministic rejections (invalid output after
    the repair pass, quality-gate refusals) are still set aside;
  - each diary group is saved as soon as it finishes, so an interrupted run
    keeps the work it already completed;
  - progress is recorded after every group, so a long drain is not reported as
    stuck, while a run without progress for two hours still is;
  - maintenance gives consolidation its own 12-hour budget
    (`ARIADNE_MAINTENANCE_CONSOLIDATE_TIMEOUT`); memfile sync keeps 20 minutes.

## Upgrade

Update from the tray. The consolidation pipeline revision moves to
`atomic-v3`, so batches deferred by earlier releases, including those cut off
by the old deadline, are reconsidered once by the next maintenance run. The
first run after the upgrade can therefore take longer than usual. Memories,
backups and settings are kept.

## Verification

Regression tests cover a launchd job that lingers after `bootout`, transient
and persistent `bootstrap` failures, in-run retry of transient model failures,
no retry of deterministic rejections, group-wise batching, the separate
consolidation timeout, and health during a long drain with and without
progress. `go build`, `go vet` (darwin, linux, windows), `go test -race`,
`golangci-lint` v2.11.4 and `govulncheck` (0 reachable vulnerabilities) pass on
go1.26.11.
