# Ariadne v0.8.28

A hotfix for the v0.8.27 update path and for misleading maintenance health
after a reboot.

## Fixed

- **Tray updates and fresh installs no longer fail on the Go checksum.**
  `go.dev/dl/<file>.sha256` now returns an HTML page instead of a digest, so the
  v0.8.27 bootstrap rejected the genuine Go 1.26.11 tarball with a checksum
  mismatch. `install.sh` now downloads Go and its SHA-256 from `dl.google.com`,
  accepts only a 64-character hexadecimal digest, and replaces the existing
  `~/.ariadne/go` only after the new tarball is verified.
- **A reboot during maintenance is reported as an interruption, not a hang.**
  A `running` or `retrying` maintenance record written before the operating
  system started cannot belong to a live process. Health now reports
  "maintenance interrupted by a system restart" on macOS, Linux and Windows;
  the next scheduled run retries it. The two-hour stuck timeout still applies to
  runs that started after boot.

## Upgrade

If an update to v0.8.27 failed with `checksum mismatch`, update again from the
tray: the tray fetches the installer of the release it installs, so v0.8.28
upgrades directly. No data, configuration or behavior changes beyond the fixes
above; memories, backups and settings are kept.

## Verification

Regression tests cover maintenance interrupted before boot (running and
retrying), live runs after boot keeping the stuck timeout, unknown boot time,
and the platform boot-time readers. The Go bootstrap was exercised end to end
with an empty home directory and no Go on `PATH`, and rejects a non-digest
checksum. `go build`, `go vet` (darwin, linux, windows), `go test -race`,
`golangci-lint` v2.11.4 and `govulncheck` (0 reachable vulnerabilities) pass on
go1.26.11.
