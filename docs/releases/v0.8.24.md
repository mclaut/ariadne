# Ariadne v0.8.24

Older `releases/vX.Y.Z-<suffix>/previous-runtime` directories now follow the same
single-copy policy as `backups/previous/runtime`, closing a gap that left old
runtime copies outside rotation.

## Changed

- Migration runs after runtime capture, on same-version reinstall, after backups,
  and through `ariadnectl backup-retention runtime-cleanup`.
- A legacy copy must match the exact inventory of a restored full recovery set.
  The canonical runtime must pass an independent copy/restore, checksum and version
  check before the obsolete copy can be removed. Older versions and byte-identical
  duplicates of the same version are eligible; changed, newer, unknown or in-use
  copies remain protected.
- Old manifests, application metadata, sidecar audit data and complete retired-file
  inventories are preserved under `backups/runtime-audit`. Existing audit archives
  are immutable and remain outside rotation.
- Cleanup targets only `previous-runtime`. Installed programs under release `bin`
  directories and open MCP clients are not interrupted. No-replace renames, repeated
  inventory/process-use checks and rollback guard the final removal.

## Verification

Tests cover preserved audit and active-image sentinels, failed recovery, changed
files, missing proof, newer versions, same-version different and identical payloads,
busy copies, repeated cleanup and same-version reinstalls without replacing the
canonical keeper. Go tests, race checks, build/lint, native Windows/Linux CI and
rendered EN/UK site checks gate publication.

The local migration removed two obsolete copies only after verifying the retained
runtime and saved every existing audit file unchanged. Full recovery sets remain
sealed point-in-time copies; their normal verified rotation policy is unchanged.
