## What's new

- **One Qdrant owner.** Status now reports every loaded Ariadne Qdrant service
  job and treats duplicate ownership as unhealthy. Service controls and the
  installer normalize old versioned jobs to the canonical service without
  deleting data or historical plist files, preventing WAL lock retry storms.
- **Repair-aware maintenance.** Diary consolidation now processes one captured
  session per generation batch, then coalesces and deduplicates validated
  same-day outputs. A local quality pass gives invalid model output one focused
  correction attempt. Deterministic language, schema, artifact, and quality
  failures receive a model-and-pipeline revision marker, so unchanged input is
  not replayed every day. Safe `complete_with_deferred` work remains observable
  without making an otherwise healthy tray orange.
- **Independent consolidation model.** Capture can remain on a small model while
  `ARIADNE_CONSOLIDATION_MODEL` and `ARIADNE_CONSOLIDATION_JUDGE_MODEL` select a
  stronger local curator. Dry-run consolidation no longer appends production
  activity state.
- **Resilient, explainable tray.** The macOS tray restarts after an abnormal
  exit but still respects an explicit clean Quit. Start and exit reasons are
  appended to the tray log so a missing icon is diagnosable.
- **A doctor that tells the truth.** The diagnostic resolves the active
  immutable runtime, reports its version, checks Codex and Claude MCP paths,
  consumes full health status, audits launchd ownership, exposes low token
  attribution, and warns about runaway logs and storage. Green, degraded, and
  failed outcomes are distinct.

## Compatibility and upgrade

- No MCP tools or payload fields changed.
- Existing memories, archived diary sources, metrics, snapshots, plist files,
  and runtime versions remain intact.
- On macOS, the installer may briefly restart an Ariadne-owned Qdrant process
  to ensure exactly one canonical launchd job owns the data directory.
- Deterministic consolidation failures remain active and append-only. They are
  reconsidered when the curator model or pipeline revision changes; until then
  they no longer consume retry delays or keep the health indicator orange.
