# Ariadne v0.8.4

This release makes project boundaries explicit from storage to the desktop.
Recall is project-scoped by default, secrets are rejected or quarantined before
normal retrieval, and every deliberate cross-project access requires a visible,
short-lived human decision.

## Visible human approval

- **System warning, not a hidden badge.** Pending cross-wing memory and
  protected-resource requests immediately open a localized system dialog.
  macOS uses its native caution window, Windows a system popup, and Linux
  KDialog or Zenity when available. The tray queue remains the fallback and
  audit view.
- **Fail-closed interaction.** Approve, Deny, and Later are explicit. Closing
  the window, pressing Escape, choosing Later, receiving an unknown response,
  or lacking a dialog provider never grants access. A still-pending request is
  shown again after one minute without opening duplicate windows.
- **One authorization path.** The system window writes through the existing
  append-only approval manager; it cannot bypass session, collection, TTL, or
  one-shot rules.

## Project isolation and secret safety

- **Default-deny project scope.** Semantic `memory_recall` and all saves require
  an active `wing`. Session hooks resolve the nearest repository root or an
  explicit `.ariadne-wing` marker. A readable sibling repository is not
  permission to borrow its memory, `.env`, endpoints, or configuration.
- **Deterministic secret guard.** MCP/store saves reject private keys,
  credential URIs, known token formats, and explicit secret assignments.
  Import and hook capture redact values, consolidation validates its output,
  and exact recall applies defensive redaction.
- **Append-only quarantine.** `ariadnectl quarantine-secrets` is a metadata-only
  dry-run by default. Applied quarantine preserves the original payload,
  vector, previous status, and audit history while excluding the record from
  normal recall. Reconciliation restores status without erasing history.

## Scoped cross-project memory

- **Human approval replaces `all_wings` as authority.** A cross-wing recall
  first creates a pending request. Approval lasts 15 minutes and is bound to
  the requesting MCP session, active wing, and collection. Curated-memory
  approval does not silently open the raw session archive.
- **Origin-aware ranking.** Approved external candidates receive a 0.70 origin
  weight and normally occupy at most two of five results when local matches are
  available. Every result discloses whether it is local or cross-wing.
- **Separate protected-resource grant.** `credential_access` requests an exact
  source wing, target wing, resource name/path, and purpose. Approval lasts five
  minutes and is consumed once. Ariadne never reads, returns, or stores the
  credential value.
- **Append-only audit.** Requests, decisions, and one-time consumptions are
  separate private JSON records. `ariadnectl approvals` is deliberately
  read-only and cannot approve requests.

## Compatibility and security boundary

- Existing memory payloads, vectors, IDs, snapshots, and historical statuses
  remain intact.
- MCP clients must now provide `wing` for semantic recall. Cross-project clients
  retry with the returned `approval_id` only after the human decision.
- Credential approval is an audited agent-policy handshake, not an operating-
  system credential broker or Keychain/Touch ID integration. The client must
  still enforce the exact approved resource and purpose.
