## What's new

- **Scoped append-only memory identity.** The same text can live independently
  in different projects and rooms. Moving a memory writes the destination
  record first and retains the original as superseded history, with lineage
  metadata for exact-ID audit.
- **Incremental, non-destructive memfile sync.** Unchanged files require zero
  embedding calls. Changed revisions are stored before older chunks are marked
  superseded, missing source files become orphaned instead of being deleted,
  and original observation times are preserved.
- **Safer diary consolidation.** Work is bounded by batch size and context
  limits, model output must pass schema and quality checks, and an empty result
  needs a later confirming pass. Failed promotion leaves source diary entries
  active for retry.
- **Observable maintenance with bounded retries.** The daily runner retries
  transient failures with capped backoff, records append-only outcomes, blocks
  consolidation after a partial sync, and exposes failed, partial, stuck, or
  stale state in status and the tray. Maintenance can also be run immediately
  from the tray.
- **Historical ranking and timestamps.** Recall adds a bounded rerank for source
  quality, explicit temporal intent, and oversized context without applying
  blanket age decay to durable decisions. `memory_save` accepts `occurred_at`
  for facts whose event time differs from capture time.
- **Auditable operations and honest accounting.** Status reports maintenance,
  storage, backups, and logs; export preserves full 64-bit IDs and lifecycle
  metadata; token attribution remains fractional and never invents savings for
  unknown delivery.

## Compatibility and upgrade

- Existing legacy records remain available. A normal save or memfile sync
  creates the scoped v2 representation first and marks the legacy record
  superseded; it does not erase history.
- `memory_move` now returns the new scoped ID while the original remains
  retrievable through exact ID or `include_archived: true`.
- No MCP tools were removed. `occurred_at` and lifecycle audit fields are
  additive.
- macOS and Linux installers schedule the retry-bounded maintenance runner at
  04:30. systemd uses a persistent timer; launchd calendar jobs catch up after
  the next wake while the agent remains loaded.
