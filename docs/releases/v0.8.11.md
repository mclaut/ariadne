# Ariadne v0.8.11

This release guarantees that Ariadne presents one desktop tray icon even when
historical autostart definitions or a manual launch try to start more copies.
It also makes macOS launchd ownership self-healing and observable.

## Root cause

Previous immutable local activations used versioned launchd labels. The normal
installer later booted out only `com.ariadne.tray` and `com.ariadne.sync`, so
older `com.ariadne.tray.*` and `com.ariadne.sync.*` jobs remained loaded. Their
plist files also stayed in `~/Library/LaunchAgents`, causing macOS to load every
historical tray again at the next login. One affected machine started 22 tray
processes simultaneously.

## Fixed

- **Cross-platform single-instance tray.** The tray acquires a non-blocking
  file lock on macOS/Linux or a named mutex on Windows before initializing the
  status item. A duplicate exits successfully, while the lock is automatically
  released when the owning process exits or restarts.
- **Complete launchd reconciliation.** Every install enumerates and boots out
  canonical and versioned tray, maintenance, and Ariadne-owned Qdrant jobs
  before bootstrapping one canonical definition for each service.
- **No stale login resurrection.** Versioned plist files are moved out of
  `~/Library/LaunchAgents` so they cannot return after reboot or login.

## Added

- **History-preserving plist archive.** Superseded launchd definitions are
  retained under Ariadne's runtime archive, with collision-safe names. The
  legacy Swift monitor plist follows the same non-destructive path.
- **Actual process-count diagnostics.** `doctor.sh` checks the number of running
  tray processes in addition to launchd labels and reports duplicates as a
  failure.
- **Regression coverage.** Tests prove that a second process cannot acquire the
  Unix lock, that a replacement can acquire it after release, that launchd
  label parsing is prefix-safe, and that archival preserves canonical,
  unrelated, and previously archived files.

## Compatibility

- No memory, Qdrant payload, metric, log, backup, or historical plist is deleted.
- Multiple `ariadne` MCP stdio processes remain expected: each active client
  session owns its own server process. The singleton rule applies to the desktop
  tray and shared background services.
- Existing canonical configuration and environment values remain supported.

## Verification

- full `go test -race ./...`, `go build ./...`, and `golangci-lint run`
- Windows amd64 cross-build of the named-mutex implementation
- live macOS reproduction from 22 tray processes to one canonical process
- deliberate duplicate launch exited cleanly without adding an icon
- launchd restart changed the tray PID while retaining exactly one tray process
- one canonical Qdrant job, green collection, and full-stack doctor verification
- production site lint, build, and rendered English/Ukrainian tests
