# Ariadne v0.8.10

This release makes Ariadne's token-attribution and corpus-coverage metrics
auditable. It fixes a real pagination precision bug, separates current memory
from retained history, distinguishes measured provenance from estimates, and
makes legacy backfill explicitly opt-in.

## Root causes

- Qdrant's `next_page_offset` was decoded through Go's default JSON
  `float64` representation. Unsigned 64-bit point IDs above `2^53` could lose
  precision and cause an attribution scan to skip or repeat pages.
- The corpus profile counted recallable memories together with archived,
  superseded, orphaned, and quarantined records retained for append-only audit.
- Legacy `x8-v1` estimates were presented alongside directly measured source
  attribution without a clear boundary.
- Gap reporting classified consolidation and manual records as diary gaps, and
  the backfill command wrote by default unless `--dry-run` was supplied.
- Agent guidance could be read as permission to attach source-token estimates
  without a bounded source, inflating the apparent attribution coverage.

## Fixed

- **Lossless Qdrant pagination.** The raw JSON representation of
  `next_page_offset` is preserved between scroll requests, so every unsigned
  64-bit ID round-trips exactly.
- **Recallable corpus is the headline denominator.** Active memories are
  reported separately from inactive or security-excluded history.
- **Safe attribution backfill.** `ariadnectl backfill-attribution` is read-only
  by default and writes only with `--apply`; conflicting `--apply --dry-run`
  flags return a usage error. Archived, superseded, orphaned, and quarantined
  records are never candidates.

## Changed

- **Measured and estimated provenance are separate.** Directly source-backed
  token attribution no longer blends with conservative `attribution_estimate`
  records.
- **Gaps retain their origin.** Diary/capture, consolidation, and manual gaps
  are counted independently so operators can choose the correct remediation.
- **Agent-side accounting is bounded.** Codex and Claude skills now require a
  defensible processed source for `source_tokens`. A later recall of an
  unattributed memory is reported as unattributed delivery, not mislabelled as
  measured savings or pure overhead.

## Compatibility

- No destructive data migration is required.
- Existing append-only memories and attribution estimates remain intact.
- The safer backfill CLI default is intentionally incompatible with scripts
  that relied on implicit mutation; add `--apply` after reviewing the dry-run.
